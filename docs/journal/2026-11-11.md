## 막힌 점과 해결

- **pfSense 시계 9시간 앞섬 → VPN 인증서 "not yet valid".** VMware가 한국 시각을 RTC로 넘기는데 FreeBSD는 UTC로 읽음. `rtc.diffFromUTC = "0"`(vmx), pfSense 시각 UTC로 맞추고 시간대 Asia/Seoul, 인증서 다시 발급.
- **VNC 자동 입력에서 Shift 문자 깨짐**(`(`→`9`, `"`→`'`, 대문자→소문자). 문자마다 Shift를 눌러 보내는 입력기로 해결(콘솔에서 SSH 키 등록 1회만 사용).
- **OpenVPN 클라이언트 2개를 한 PC에서:** DCO 어댑터는 tap 드라이버를 기대해 실패 → TAP 어댑터 2개(`OpenVPN TAP-Windows6`, `haedam-vpn-tap-d`) + `windows-driver tap-windows6`.
- **`ifconfig-pool` 사용자 옵션이 `server` 지시어와 충돌**해 서버가 안 뜸 → 제거(고정 주소 3개만 쓰므로 영향 없음). 팀의 동적 풀 .101~.199와는 다름.
- **같은 서브넷에 VPN 주소 두 개 → 호스트가 출발지로 C(.3)를 골라** n8n → 포털 호출이 pfSense 규칙(D .100만 허용)에 막힘. 실습 TAP 어댑터 우선순위를 D 5·C 50으로 조정 → 출발지 .100.
- **pfSense 대응 도구는 root(uid 0)에서만 실행**(`geteuid() != 0` 거부). 팀 계획의 별도 계정 대신 admin(uid 0)에 전용 키를 `from="10.250.0.100",restrict,command="/usr/local/sbin/haedam-pf-response"`로 등록. 도구 SHA-256 `f0eea297…`(팀 PR64 검토본과 같음). D에서 status `ok`, C(.3)에서는 연결 자체가 막힘.
- **MySQL 저장소 키(2023) 만료** → 2025 키 사용.
- **포털 마이그레이션 경로:** 일반 `pip install`이면 앱이 site-packages 기준으로 migrations를 찾음 → 편집 모드 설치.
- **메모리:** VM 설치 때 2GB로 만든 포털·DB VM을 1GB로 낮춤(실행 중 vmx 수정은 종료 때 덮어써지므로 끈 뒤 수정).

## 남은 막힘 — 사용자 조치 필요

- **Windows 방화벽**: VPN 어댑터 2개가 "공용"이라 pfSense·포털 VM → 호스트(.3·.100)로 들어오는 syslog·GELF·Wazuh agent 연결이 막힘. pfSense에서 `nc -z 10.250.0.100 12201` 닫힘 확인. 보안 설정이므로 자동으로 바꾸지 않았고 `tools/windows/allow-lab-firewall.ps1`(출발지 10.250.0.0/24·10.10.30.0/24, 필요한 포트만)을 사용자가 관리자 PowerShell에서 실행.
